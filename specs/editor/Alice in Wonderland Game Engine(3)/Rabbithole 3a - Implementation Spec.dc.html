Rabbithole editor shell

Implementation spec for layout 3a — full-bleed viewport, glass overlay panels, ECS inspector. Written against the mockup file; every value below is authoritative over the mockup's pixels where the two disagree.

1 · Shell geometry

One layer: the 3D viewport is the full window. Every panel is an overlay floating above it, inset from the window edge — there are no dock splitters and no reserved gutters. Panels never resize the viewport; they occlude it.

RegionPlacementNotes
viewportfills the window, edge to edge, behind everythingCamera framing must assume the centre ~55% is unobstructed.
titlebartop-left, inset 18px / 16px; no background plateScene name + breadcrumb only. Text directly over the scene.
statstop-right, inset 18px / 16px; no plateOptional; hidden by default in a shipping build.
left railwidth 238px, inset left 18px, top 52px, bottom 18pxTwo stacked panels, 10px gap: scene tree (44% of rail height) over asset browser (56%). Both scroll independently.
right railwidth 290px, inset right 18px, top 52px, bottom 18pxSingle panel: entity inspector. Scrolls.
centre foothorizontally between the rails (left 284px, right 326px), bottom 18pxTwo rows, 8px gap: pill toolbar (centred, hugs content) above the full-width log strip.

Minimum window: 1080 × 640. Below 1180px wide the centre foot's command hint truncates before the rails shrink; below 900px the left rail collapses to a 44px icon strip (not mocked — ask before building).

2 · The panel surface

Every overlay panel is the same object. Build it once.

PropertyValue
background#141622 at 62% opacity
backdrop-filterblur(14px) — required; without it the scene reads through and text fails contrast
border-radiusvar(--radius-lg)
elevationvar(--shadow-sm) — one step only, never stacked
padding10px (rail panels) · 12px (inspector)
section header10px / 500 / .1em tracking / uppercase / --color-neutral-500, with a right-aligned count or affordance

The toolbar and log strip are the same surface at #101220 / 78–82% and blur(16px) — darker because they sit over the brightest part of the floor. Toolbar radius is a full pill (99px); the log strip uses --radius-md.

If your UI library can't do backdrop-filter, raise panel opacity to 92% and drop the blur. Do not compromise by using a semi-transparent panel without blur — 3D detail behind text is the one thing this layout can't tolerate.

3 · Scene tree (“Warren”)

A flat-indent tree of entities. Row height 22–24px, indent 16px per level, 12.5px label.

ElementSpec
disclosure9px glyph, 9px column reserved even on leaves so labels align
type mark8px square rotated 45° = entity · 7px circle = environment/light · 8×6px rounded rect = camera · monospace / = script or system group. Colour --color-neutral-600, or --color-accent when selected.
component countright-aligned, 10px monospace, --color-neutral-600. This is the ECS tell — show it on every entity row.
selected rowbackground --color-accent @ 20%, text --color-accent-100, radius --radius-sm. No left bar in this layout (that belongs to the docked variants).
hover row--color-neutral-100 @ 6%
footer10.5px, --color-neutral-600: “N entities · M components”

Behaviours: click selects, double-click renames inline, drag re-parents (drop line at 1px --color-accent), ⌫ deletes with an undo toast. Multi-select with shift/cmd puts the inspector into the shared-components state (§5.4).

4 · Asset browser (“Curiosities”)

Deliberately a list, not a thumbnail grid: the project is expected to carry hundreds of assets, and names are the primary key. Thumbnails cost the vertical space this panel needs for results.

ElementSpec
search26px tall, radius --radius-sm, fill --color-neutral-100 @ 9%, leading ⌕, trailing ⌘P hint. Filters as you type; substring match on name and extension; results ranked by recency of use.
type filtersRow of small tags (10px): all / mesh / mat / tex / lua / audio. Active = .tag-outline, inactive = .tag-neutral. Single-select.
row22px: type mark (8–9px, same vocabulary as the tree) · name, ellipsised at the middle if long · right-aligned size in 9.5px monospace.
row stateshover as tree; selected as tree; a row whose asset is used by the selected entity gets its mark in --color-accent.
footer“N of TOTAL match “query”” — replaces the count when a query is active.
scrollingVirtualise. Assume 10k rows. Scrollbar is overlay-style, 6px, --color-neutral-700.

Drag an asset row into the viewport to instantiate it as an entity at the drop point; drag onto an inspector slot to assign it. Both need a 1px accent outline on the valid drop target.

5 · Entity inspector (“Looking glass”)

The inspector is a list of components, not a fixed form. It renders whatever array the entity holds, in the order the world stores them, with no privileged Transform section — Transform simply happens to be first.

5.1 Header

Entity mark · name (14px / 500) · id in 10.5px monospace --color-neutral-600 · overflow ⋯. Below it, a components N label in the section-header style.

5.2 Component card

ElementSpec
cardradius --radius-md, fill --color-neutral-100 @ 7%, 6px gap between cards
card header6×8px padding: disclosure (8px) · type mark (7px rotated square) · name in 12px / 500 heading · optional 10.5px monospace summary (mass, language) · enable checkbox right-aligned
type mark colour--color-accent = engine-core component · --color-accent-2-500 = script/user component · --color-neutral-500 = collapsed or disabled
enable checkbox13px .radio + .dot. Unchecked means the component stays on the entity but its system skips it. Distinct from removal.
collapsedHeader row only, same fill. Collapse state persists per component type, not per entity.
field rowLabel column 38–52px, 11px --color-neutral-500; value chips 24px tall, --color-neutral-900 fill, radius --radius-sm, 11px monospace.
vector fieldThree equal chips in a grid, 4px gap. Axis letters are optional and tinted x/y/z = accent / neutral-300 / accent-2 when shown.
dirty fieldinset 0 0 0 1px var(--color-accent) on the chip until the value is committed or the frame advances.
asset referenceValue chip with the asset's type mark and name, ellipsised; click reveals it in Curiosities, drag-drop reassigns.
reorder / removeDrag the card header to reorder; remove via the ⋯ menu. Never a visible ✕ — accidental component loss is the expensive mistake here.

5.3 Add component

A 30px dashed-border row (--color-neutral-700) reading “add component” with an ⌘⇧A hint. It opens a filtered searchable list of registered component types, grouped engine / script, excluding types the entity already has when the type is single-instance. This is the only affordance for adding — no separate menu.

5.4 Other states

Nothing selected: panel shows the scene's own properties (environment, active camera, systems list) rather than an empty state. Multi-select: show only components common to the whole selection; fields whose values differ read — and edit all. Footer line, 10.5px --color-neutral-600: “systems touching this entity: …”.

6 · Toolbar and log (“Chatter”)

ElementSpec
gizmo groupThree 28×26px pill buttons — translate / rotate / scale. Active: --color-accent @ 20% fill, --color-accent-100 glyph. Keys W E R.
divider1px × 20px, --color-neutral-100 @ 14%

play.btn .btn-primary, 28px, pill radius, never shrinks. Toggles to a stop treatment while running and the viewport gains a 1px accent inner border.
log strip (collapsed)32px: title · unread badge (accent-800 fill, accent-100 text) · severity glyph · the newest line, ellipsised · ⌥L · chevron. Clicking anywhere expands.
log strip (expanded)Grows upward to 224px over the viewport, same surface. Columns: time · source (52px: assets / world / systems / script / audio) · severity glyph · message. 11.5px monospace, 1.6 line-height, rows never wrap — ellipsis and a details popover instead.
severity✓ --color-accent-400 · · --color-neutral-600 · ! --color-accent-300 on a row tinted --color-accent @ 12% · errors use the same treatment one ramp step lighter.

A script error auto-expands the strip once per play session; warnings only bump the badge. Clicking a script line focuses that entity and reveals the offending component.

Numeric values are monospace throughout (system ui-monospace stack) — coordinates, ids, sizes, timestamps and counts. This is load-bearing: it's how a value reads as editable data rather than label text.

8 · Type and hit-target floor

8px is the smallest glyph (disclosure arrows), 9.5px the smallest text (file sizes), 10px the smallest label (section headers, tags). Interactive rows are 22px minimum with a 26px hit box; buttons and inputs 26–30px. Don't go below these — the layout is dense on purpose but stops here.

9 · Wonderland theming

The theme lives in names and one motif, nothing structural: panel titles (Warren, Curiosities, Looking glass, Chatter), the play verb (“Fall in”), the command-palette hint, the rabbit-silhouette mark in the titlebar, and the checkerboard ground plane in the viewport. Every one of these is a string or a single asset — keep them in one place so the theme can be switched off. Component type names, field labels, log sources and keyboard hints stay literal; a beginner should never have to translate a metaphor to find a property.

10 · Not specified here

Command palette contents, script editor, material editor, the icon-collapsed rail, play-mode chrome, and the systems/world inspector are all referenced above but not designed. Ask before implementing them from imagination.

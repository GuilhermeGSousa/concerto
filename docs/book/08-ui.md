# 8. User interface

Concerto's UI is made of entities, like everything else. A UI element is an
entity with a `UINode` (its layout), and optionally a `UIMaterial` (a filled,
rounded, bordered box) and a `UIText`. Children are laid out inside their
parent with flexbox, computed by Taffy. The editor is built from the same
pieces, so anything it does, a game can do.

`ui-showcase` puts every element on one screen; run it with
`cargo run -p ui-showcase`.

## Building with the theme

The `UITheme` resource holds the colors, spacing, radii and font sizes, and
builds themed elements. Its builders return values you spawn directly; the
modifier methods come from the traits in `concerto::ui::elements::prelude`.

```rust
use concerto::ui::{elements::prelude::*, theme::UITheme, transform::UIValue};

fn spawn_menu(mut cmd: CommandQueue, theme: Res<UITheme>) {
    let theme = &*theme;
    cmd.spawn(
        theme
            .panel()
            .size(UIValue::Px(260.0), UIValue::Percent(100.0))
            .column()
            .gap(theme.spacing_sm)
            .padding(theme.spacing_md),
    )
    .add_child(theme.label("Settings").large())
    .add_child(theme.checkbox("Invert mouse", false))
    .add_child(theme.slider(0.5, 0.0, 1.0))
    .add_child(theme.text_field("Player name"))
    .add_child(theme.button("Start").on_click(start_game));
}
```

| Builder | Element |
|---|---|
| `canvas()`, `panel()`, `card()` | surfaces at increasing elevation |
| `row()`, `column()` | an invisible flex container |
| `label(text)` | text |
| `button(text)` | a clickable button; `.tab()`, `.ghost()` and `.selected(bool)` restyle it |
| `text_field(placeholder)` | a one-line text input |
| `checkbox(text, checked)`, `slider(value, min, max)` | controls |
| `popup()`, `dropdown(trigger)` | an opaque floating menu body |
| `chip(text)`, `divider()` | the rest; see `crates/ui/src/elements` |

Common modifiers:

| Group | Modifiers |
|---|---|
| Size | `width`, `height`, `size`, `min_width`, `max_width`, ..., `grow`, `shrink`, `fixed` |
| Flex | `row`, `column`, `gap`, `padding`, `margin`, `align_items`, `justify` |
| Text | `font_size`, `small`, `large`, `muted`, `mono`, `weight`, `color`, `single_line` |
| Shape | `radius`, `border`, `bordered`, `borderless` |
| Other | `clipped`, `hidden`, `z_index` |

Sizes are `UIValue::Px(logical_pixels)`, `UIValue::Percent(...)` or
`UIValue::Auto`. Every top-level UI entity is a root laid out over the whole
window.

## Reacting to the user

A click is a signal sent to the clicked entity (chapter 4). Attach its
listener with `on_click`:

```rust
use concerto::{
    ecs::signal::On,
    ui::interaction::UIClick,
    window::input::MouseButton,
};

fn start_game(on: On<UIClick>, mut state: ResMut<GameState>) {
    if on.signal().button == MouseButton::Left {
        *state = GameState::Playing;
    }
}
```

`on_double_click` works the same way. A checkbox and a slider have
`on_change`, which receives `UICheckboxChanged { checked }` or
`UISliderChanged { value }`:

```rust
theme
    .checkbox("Invert mouse", false)
    .on_change(|on: On<UICheckboxChanged>, mut settings: ResMut<Settings>| {
        settings.invert_mouse = on.signal().checked;
    })
```

A listener that needs to know which item it belongs to captures it, rather
than reading a component back:

```rust
fn pick_level(index: usize) -> Listener<UIClick> {
    (move |_on: On<UIClick>, mut level: ResMut<SelectedLevel>| {
        level.0 = index;
    })
    .into_listener()
}

for (index, name) in levels.iter().enumerate() {
    column.add_child(theme.button(name).on_click(pick_level(index)));
}
```

Text fields report through events, from `concerto::ui::text_input`:
`UITextInputChanged { entity, value }` on every edit, `UITextInputSubmitted`
on Enter and `UITextInputCancelled` on Escape. A field supports selection
with the keyboard and mouse, the system clipboard, word movement and undo,
and a value too long for it scrolls to keep the caret visible.
The focused widget is in the `FocusedWidget` resource.

## Updating what is shown

Change a component and the UI follows, through change detection:

```rust
fn show_health(players: Query<&Health, With<Player>>, labels: Query<&mut UIText, With<HealthLabel>>) {
    let Some(health) = players.iter().next() else {
        return;
    };
    let text = format!("HP {:.0}", health.current);
    for mut label in labels.iter() {
        if label.text != text {
            label.text = text.clone();
        }
    }
}
```

Compare before writing: a write marks the text changed, which re-shapes it
and lays it out again even when nothing differs. A label whose text changes
often, such as a counter, is cheapest when its size can never depend on its
text: give it a `Px` width and height and make it unable to shrink below them,
with `.fixed()` or a minimum size.

## Without the theme

The builders are a convenience. The raw components are always available, as
the tech demo's overlay shows:

```rust
use concerto::ui::{
    material::UIMaterial,
    node::{UINode, UIRect},
    text::{FontFamily, UIText},
};

cmd.spawn((
    UINode::default()
        .with_size(UIValue::Px(230.0), UIValue::Px(46.0))
        .with_padding(UIRect::axes(6.0, 10.0)),
    UIMaterial::flat(Color::rgba(0.0, 0.35, 0.1, 0.6)),
))
.add_child((
    UINode::default().with_flex_grow(1.0),
    UIText {
        text: "grounded: --".to_string(),
        font_size: 12.0,
        line_height: 16.0,
        font_family: FontFamily::Monospace,
        ..Default::default()
    },
));
```

A `UIMaterial` fills its box with `color`, or with a gradient the shader
computes per pixel when `gradient` is set. The `UIGradient` kinds are
`SaturationValue { hue }`, a saturation/value square at one hue;
`Hue`, a strip through every hue; and `Alpha { color, cell }`, a color fading
in from transparent over a checkerboard. Each replaces only the fill's RGB:
its alpha still comes from `color`, and borders, rounding and rotation apply
as usual.

Lists, trees, scroll areas, split panes, tabs and anchored popups live in
`concerto::ui::{list, tree, scroll, widgets, anchor}`; `ui-showcase` uses
each of them. An anchored panel that Escape closes receives `UIPanelEscaped`,
so a popup can undo what it changed; a press outside it closes it without
that signal.
